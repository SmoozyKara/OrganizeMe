# Органайзер приоритетов — документация к ядру структур данных

Документ описывает текущее состояние ядра бизнес-логики: структуры данных,
файлы проекта и все функции. Относится к этапу «Структуры данных и
бизнес-логика ядра».

## Структура файлов

Ядро разбито на два модуля по смыслу — то, что касается отдельного элемента,
и то, что касается списков/коллекции списков. `.h`-файл — объявления
(что существует), `.cpp` — реализация (как это работает).

```
task_item.h / task_item.cpp   — TaskItem и операции над одним списком элементов
task_list.h / task_list.cpp   — TaskList, Organizer, слияние списков
main.cpp                      — точка входа, использует оба модуля
```

Зависимость — только в одну сторону: `task_list.*` подключает `task_item.h`
(потому что `TaskList` хранит внутри себя `vector<TaskItem>`), но не наоборот.
`task_item.*` ничего не знает про `TaskList` и не должен её подключать —
поэтому функции работы с элементами принимают `std::vector<TaskItem>&`,
а не `TaskList&`.

## task_item.h / task_item.cpp

### `TaskItem`

```cpp
struct TaskItem {
    int id;
    int priority;
    std::string text;
};
```

Один элемент (задача) внутри списка.

| Поле       | Назначение                                                                 |
|------------|-----------------------------------------------------------------------------|
| `id`       | Уникальный идентификатор элемента. Присваивается автоматически при добавлении через `AddElementToList`, никогда не переиспользуется. Используется вместо позиции в массиве — позиция нестабильна и меняется при каждой вставке/удалении. |
| `priority` | Приоритет задачи. **1 — наивысший приоритет.** Чем больше число, тем ниже приоритет. |
| `text`     | Текстовое описание задачи.                                                 |

**Инвариант:** вектор `TaskItem`, с которым работают функции ниже, всегда
остаётся отсортированным по `priority` по возрастанию. Инвариант
поддерживается только этими функциями — при прямой правке вектора в обход
них инвариант можно случайно нарушить.

### `int GenerateNextId()`

Возвращает очередной уникальный `id` для нового элемента. Счётчик —
глобальный на всё приложение (общий для всех списков), реализован через
`static`-переменную внутри функции.

При добавлении сохранения данных на диск (персистентности — то есть чтобы
данные не пропадали после закрытия приложения) счётчик нужно будет
восстанавливать из максимального уже сохранённого `id` при загрузке, иначе
возможны коллизии с уже использованными id.

### `void InsertSorted(std::vector<TaskItem>& items, TaskItem elem)`

Вставляет уже полностью готовый элемент (id уже выставлен заранее) в
правильную позицию по `priority`, через `std::upper_bound` (бинарный поиск,
`O(log n)`) с явным компаратором по `.priority` — без него сравнение шло бы
по умолчанию, по всем полям структуры сразу, что некорректно.

Это общий «кирпичик», вынесенный отдельно, чтобы не дублировать логику
вставки в `AddElementToList` и `ChangeElementPriority`.

### `void AddElementToList(std::vector<TaskItem>& items, TaskItem elem)`

Добавляет **новый** элемент: присваивает ему `id` через `GenerateNextId()`,
затем вызывает `InsertSorted`. Вызывающий код не должен сам придумывать `id`.

`elem` принимается по значению (не по ссылке), потому что функция меняет
`elem.id` перед вставкой — это не должно быть видно как побочный эффект на
переменной вызывающей стороны.

### `void DeleteElementFromList(std::vector<TaskItem>& items, int id)`

Удаляет элемент с указанным `id`. Поиск — линейный, через `std::find_if`
(`O(n)`), намеренно по `id`, а не по индексу — индекс нестабилен.

Если элемент не найден — ничего не удаляет, выводит предупреждение в
`std::cerr`. Временное решение; возможно, в будущем стоит заменить на
возврат `bool`/`std::optional`, в зависимости от общей стратегии обработки
ошибок в приложении.

### `void ChangeElementPriority(std::vector<TaskItem>& items, int id, int new_priority)`

Меняет приоритет уже существующего элемента, сохраняя его `id`.

Алгоритм:
1. Найти элемент по `id` (как в `DeleteElementFromList`). Не найден — вывести
   предупреждение и выйти.
2. Если новый приоритет совпадает со старым — ничего не делать (список уже
   отсортирован верно, лишняя работа не нужна).
3. Скопировать данные элемента, удалить его со старой позиции, поменять
   `priority` у копии, вставить копию заново через `InsertSorted`.

Копирование элемента делается **до** удаления из вектора: после
`items.erase(it)` итератор `it` становится недействительным, обращаться к
`*it` после этого — undefined behavior.

Порядок «сначала удалить, потом вставить», а не наоборот — иначе на
мгновение в списке будет два элемента с одинаковым `id`, что нарушает
инвариант его уникальности.

## task_list.h / task_list.cpp

### `TaskList`

```cpp
struct TaskList {
    int id;
    int rank;
    std::string name;
    std::string color;
    std::vector<TaskItem> items;
};
```

Один именованный список задач (например, «Работа»).

| Поле    | Назначение                                                                                   |
|---------|-----------------------------------------------------------------------------------------------|
| `id`    | Уникальный идентификатор списка. Никогда не меняется. Собственный счётчик, отдельный от `id` элементов (`GenerateNextListId`, а не `GenerateNextId`). |
| `rank`  | Порядок списка относительно других списков. Используется как тай-брейк при равном `priority` элементов из разных списков. **В отличие от `id`, может меняться** — например, пересчитывается при удалении другого списка. Именно поэтому операции над списками (например, удаление) должны искать список по `id`, а не по `rank` — по той же причине, по которой `TaskItem` ищется по `id`, а не по позиции в массиве. |
| `name`  | Имя списка, например «Работа».                                                                |
| `color` | Цвет списка, хранится как hex-строка (например, `"#FF5733"`).                                 |
| `items` | Элементы списка. Инвариант сортировки по `priority` тот же, что описан в `task_item.h`.        |

**Инвариант по `rank`:** среди всех списков в одном `Organizer` значения
`rank` всегда идут подряд без пропусков, начиная с `0` (`0, 1, 2, ...`).
Поддерживается функциями `CreateTaskList` и `DeleteTaskList` ниже.

### `Organizer`

```cpp
struct Organizer {
    std::vector<TaskList> lists;
};
```

Хранилище всех списков приложения — единая точка, через которую идёт любое
управление списками (создание, удаление, слияние всех в сводный список).

### `int GenerateNextListId()`

То же самое, что `GenerateNextId()` в `task_item.cpp`, но отдельный счётчик,
специально для `id` списков — чтобы не смешивать нумерацию списков и
нумерацию элементов внутри них.

### `void CreateTaskList(Organizer& organizer, std::string name, std::string color)`

Создаёт новый список и добавляет его в конец `organizer.lists`.

- `id` — через `GenerateNextListId()`.
- `rank` — на единицу больше, чем у текущего последнего списка
  (`organizer.lists.back().rank + 1`), либо `0`, если списков пока нет
  вообще (граничный случай, проверяется через `.empty()`).
- `items` — пустой при создании.

### `void DeleteTaskList(Organizer& organizer, int id)`

Удаляет список с указанным `id` и пересчитывает `rank` оставшихся, чтобы
инвариант «подряд без дырок» сохранялся.

Алгоритм:
1. Найти список по `id` через `find_if`. Не найден — предупреждение в
   `std::cerr`, ничего не делать.
2. Запомнить `rank` найденного списка **до** удаления (после `erase`
   итератор станет недействительным).
3. Удалить список.
4. Пройтись по всем оставшимся спискам; у каждого, чей `rank` был больше,
   чем у удалённого — уменьшить `rank` на `1`.

Шаг 4 работает именно так (не через полную пересортировку) благодаря тому,
что `rank` до удаления уже шёл подряд без дырок — значит, достаточно
«сдвинуть» только те ранги, что были больше удалённого, на единицу назад.

В цикле по `organizer.lists` важно использовать `auto&` (ссылку), а не
`auto` — иначе цикл проходил бы по копиям каждого `TaskList` (с копированием
всего `.items` внутри), и правки `rank` не отражались бы на реальных данных.

### `std::vector<TaskItem> MergeAllLists(const std::vector<TaskList>& lists)`

Сливает произвольное число списков в один сводный, отсортированный по
`priority`, с тай-брейком по `rank` списка при равенстве `priority`.

**Алгоритм — k-way merge через min-heap (`std::priority_queue`):**

1. В heap заводится по одному «кандидату» от каждого непустого списка —
   первый элемент каждого списка (наивысший приоритет в нём).
2. На каждом шаге извлекается «лучший» кандидат (см. компаратор ниже),
   кладётся в результат.
3. На освободившееся место, с той же «дорожки» (того же списка),
   подставляется следующий ещё не рассмотренный элемент, если он есть.
4. Цикл продолжается, пока heap не опустеет.

Сложность: `O(N log k)`, где `N` — суммарное число элементов во всех
списках, `k` — число списков.

`MergeCandidate` и `CandidateComparator`, использующиеся внутри алгоритма,
объявлены в **безымянном `namespace`** внутри `task_list.cpp` — это значит,
что они видны только в этом файле и нигде больше. Они нужны исключительно
как внутренние детали реализации `MergeAllLists`, поэтому в `task_list.h`
их нет — снаружи о них знать не нужно.

#### `MergeCandidate` (только в task_list.cpp)

| Поле         | Назначение                                                                 |
|--------------|-----------------------------------------------------------------------------|
| `item`       | Указатель на элемент-кандидат (не копия — чтобы не копировать `text` на каждый push/pop). Валиден, только пока жив и не мутируется переданный в `MergeAllLists` вектор `lists`. |
| `list_rank`  | `rank` списка, из которого пришёл кандидат — для тай-брейка в компараторе. |
| `list_index` | Индекс списка **в векторе `lists`** (позиция в аргументе функции, не `rank`). |
| `item_index` | Позиция элемента внутри `lists[list_index].items` — нужна, чтобы подставить `item_index + 1` после извлечения. |

#### `CandidateComparator` (только в task_list.cpp)

`std::priority_queue` по умолчанию — max-heap. Нужен обратный эффект (наверх
всплывает **наименьший** `priority`), поэтому сравнение инвертировано:
`operator()` возвращает `true`, если `a` следует считать «хуже» `b` (дальше
от `.top()`).

1. Если `priority` элементов различаются — «хуже» тот, у кого `priority`
   численно больше.
2. Если `priority` равны — тай-брейк по `rank` списка: «хуже» тот, чей
   список имеет численно больший `rank`.

## main.cpp

Точка входа. Содержит `PrintList` — отладочную функцию вывода списка
элементов в консоль (не часть бизнес-логики, используется только для
проверки в `main()`) — и демонстрационный сценарий: создание двух списков,
добавление элементов, удаление, слияние в сводный список.

**На заметку:** `main()` пока работает с `TaskList` напрямую (переменные
`work`, `home`), а не через `Organizer` — использование `CreateTaskList` /
`DeleteTaskList` через `Organizer` в `main()` ещё не показано, это можно
добавить отдельно при желании.

## Что дальше по плану

Ядро структур данных и бизнес-логики (этап 2) закрыто полностью:
добавление, удаление, изменение приоритета элементов; создание, удаление и
пересчёт `rank` списков; слияние произвольного числа списков в сводный.

Следующий пункт плана — **слой представления данных для QML**: адаптеры
поверх этого ядра (скорее всего, на основе `QAbstractListModel` /
`QAbstractItemModel`), чтобы QML мог отображать данные без прямого доступа
к внутренностям `Organizer`/`TaskList`.

Отдельно остаётся открытым вопрос **хранения данных** (JSON-файл через
`QJsonDocument` — принятое ранее предварительное решение для первой версии,
с возможностью впоследствии заменить на SQLite через `QtSql`) — на момент
этого документа ещё не реализовано.
