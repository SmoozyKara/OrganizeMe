# Органайзер приоритетов — документация к ядру структур данных

Документ описывает структуры данных и функции файла с ядром бизнес-логики
(хранение списков задач, добавление/удаление элементов, слияние списков
в сводный список по приоритету). Относится к этапу «Структуры данных и
бизнес-логика ядра» проекта.

## Структуры данных

### `TaskItem`

```cpp
struct TaskItem {
    int id;
    int priority;
    std::string text;
};
```

Один элемент (задача) внутри списка.

| Поле       | Назначение                                                                 |
|------------|-----------------------------------------------------------------------------|
| `id`       | Уникальный идентификатор элемента. Присваивается автоматически при добавлении через `AddElementToList`, не переиспользуется. Используется для поиска/удаления элемента вместо его позиции в массиве — позиция меняется при каждой вставке/удалении, id — нет. |
| `priority` | Приоритет задачи. **1 — наивысший приоритет.** Чем больше число, тем ниже приоритет. |
| `text`     | Текстовое описание задачи.                                                 |

### `TaskList`

```cpp
struct TaskList {
    int rank;
    std::vector<TaskItem> items;
};
```

Один именованный список задач (например, «Работа», «Домашние дела»).

| Поле    | Назначение                                                                                   |
|---------|-----------------------------------------------------------------------------------------------|
| `rank`  | Порядок этого списка относительно других списков. Используется как тай-брейк при равном `priority` элементов из разных списков (меньший `rank` — выше в сводном списке). Не путать с `id`: `rank` может меняться (например, при переупорядочивании списков пользователем), в то время как назначение `id` — быть неизменным идентификатором. |
| `items` | Элементы списка. **Инвариант: всегда отсортирован по `priority` по возрастанию.** Этот инвариант поддерживается функцией `AddElementToList` и не должен нарушаться при прямых манипуляциях с `items` в обход неё. |

## Функции

### `int GenerateNextId()`

Возвращает очередной уникальный `id` для нового элемента. Счётчик — глобальный
на всё приложение (общий для всех `TaskList`, а не отдельный на каждый список),
реализован через `static`-переменную внутри функции.

**Важно при добавлении сохранения/загрузки данных:** при старте приложения
`next_id` инициализируется в `1`. Если список задач загружается из хранилища
(файл/БД) с уже существующими `id`, счётчик нужно будет восстановить из
максимального сохранённого `id`, иначе новые элементы могут получить `id`,
уже занятый ранее сохранённым элементом.

### `void AddElementToList(TaskList& list, TaskItem elem)`

Добавляет элемент в список, сохраняя инвариант сортировки по `priority`.

- `elem` принимается **по значению**, не по ссылке — потому что функция
  присваивает `elem.id` перед вставкой, и это не должно быть видно вызывающей
  стороне как побочный эффект на её собственной переменной.
- Позиция вставки ищется через `std::upper_bound` (бинарный поиск, `O(log n)`)
  с явным компаратором по `priority` — без него `upper_bound` использовал бы
  сравнение всей структуры `TaskItem` по умолчанию, что было бы некорректно
  (сравнивало бы и `id`, и `text`).
- Сама вставка (`items.insert`) — `O(n)` в худшем случае (сдвиг хвоста
  вектора). При ожидаемых объёмах данных (сотни элементов на список) это
  несущественно.
- `id` элементу присваивается **внутри функции** через `GenerateNextId()` —
  вызывающий код не должен заботиться об уникальности `id` и не должен
  передавать его сам.

### `void DeleteElementFromList(TaskList& list, int id)`

Удаляет из списка элемент с указанным `id`.

- Поиск — линейный, через `std::find_if` с предикатом по `id` (`O(n)`).
  Поиск по `id`, а не по индексу, выбран намеренно: индекс элемента в массиве
  нестабилен и меняется при любой другой вставке/удалении, что делает
  удаление «по индексу» ненадёжным, если между определением индекса и
  вызовом удаления могли произойти другие операции над списком.
- Если элемент с таким `id` не найден — функция ничего не удаляет и выводит
  предупреждение в `std::cerr`. Это временное/минимальное решение; в
  дальнейшем может быть заменено на возврат `bool`/`std::optional` или
  исключение, в зависимости от того, как будет строиться обработка ошибок
  на уровне приложения в целом.

### `std::vector<TaskItem> MergeAllLists(const std::vector<TaskList>& lists)`

Сливает произвольное число списков в один сводный, отсортированный по
`priority`, с тай-брейком по `rank` списка при равенстве `priority`.

**Алгоритм — k-way merge через min-heap (`std::priority_queue`):**

1. В heap заводится по одному «кандидату» (`MergeCandidate`) от каждого
   непустого списка — первый элемент каждого списка (наивысший приоритет
   в нём, благодаря инварианту сортировки `items`).
2. На каждом шаге из heap извлекается «лучший» кандидат (см. компаратор
   ниже), кладётся в результат.
3. На освободившееся место — с той же «дорожки» (того же списка) —
   подставляется следующий ещё не рассмотренный элемент, если он есть.
4. Цикл продолжается, пока heap не опустеет (то есть все списки исчерпаны).

Сложность: `O(N log k)`, где `N` — суммарное число элементов во всех списках,
`k` — число списков. Для сравнения: наивное слияние через сортировку всего
объединённого набора с нуля было бы `O(N log N)` — выигрыш ощутим при
большом `k` относительно `N`, хотя при текущих ожидаемых масштабах проекта
(до ~2500 элементов, 10–20 списков) разница не критична на практике; выбор
сделан в первую очередь как алгоритмическая практика.

#### `MergeCandidate`

```cpp
struct MergeCandidate {
    const TaskItem* item;
    int list_rank;
    size_t list_index;
    size_t item_index;
};
```

Вспомогательная структура — «кандидат» в heap на очередной шаг слияния.

| Поле         | Назначение                                                                 |
|--------------|-----------------------------------------------------------------------------|
| `item`       | Указатель на элемент-кандидат. Указатель, а не копия — чтобы не копировать `std::string text` на каждый push/pop в heap. **Ограничение:** валиден, только пока жив и не мутируется переданный в `MergeAllLists` вектор `lists` (сейчас это гарантируется тем, что `lists` передаётся как `const&` и не изменяется внутри функции). |
| `list_rank`  | `rank` списка, из которого пришёл кандидат — используется компаратором для тай-брейка. |
| `list_index` | Индекс списка **в векторе `lists`** (позиция в аргументе функции). Не путать с `rank` — это чисто техническая позиция для доступа к `lists[list_index]`, может не совпадать с `rank`, если списки переданы не по порядку rank'ов. |
| `item_index` | Позиция элемента внутри `lists[list_index].items` — нужна, чтобы после извлечения кандидата понять, какой элемент подставить на его место (`item_index + 1`). |

#### `CandidateComparator`

```cpp
struct CandidateComparator {
    bool operator()(const MergeCandidate& a, const MergeCandidate& b) const {
        if (a.item->priority != b.item->priority) {
            return a.item->priority > b.item->priority;
        }
        return a.list_rank > b.list_rank;
    }
};
```

Функтор-компаратор для `std::priority_queue`. `std::priority_queue` по
умолчанию — max-heap (наверх всплывает «наибольший» по компаратору элемент).
Здесь нужен обратный эффект — наверх должен всплывать кандидат с
**наименьшим** `priority` (поскольку `1` — наивысший приоритет по принятой
в проекте конвенции), поэтому сравнение инвертировано: `operator()`
возвращает `true`, если `a` следует считать «хуже» `b` (дальше от `.top()`).

Логика сравнения:
1. Если `priority` элементов различаются — «хуже» тот, у кого `priority`
   численно больше.
2. Если `priority` равны — тай-брейк по `rank` списка: «хуже» тот, чей
   список имеет численно больший `rank` (то есть более приоритетный список
   выигрывает при равенстве приоритетов задач).

### `void PrintList(const std::vector<TaskItem>& list)`

Отладочная функция вывода списка элементов в консоль
(`[priority=...] text`). Не часть бизнес-логики — используется только
для проверки корректности работы остальных функций в `main()`.

## Открытые вопросы / не реализовано в этой версии

Зафиксировано для дальнейшей работы, чтобы не потерять из виду:

- **Изменение приоритета существующего элемента.** Требует отдельной функции
  (не сводится напрямую к `DeleteElementFromList` + `AddElementToList`,
  поскольку `AddElementToList` генерирует новый `id`, а при смене приоритета
  `id` элемента должен сохраниться).
- **Управление самими списками** — создание нового `TaskList`, удаление
  списка целиком, изменение его `rank`.
- **Инвариант уникальности/непрерывности `rank`** при удалении списка из
  середины — пока не определено, нужно ли пересчитывать `rank` оставшихся
  списков или допускать «дыры» в нумерации.
- **Персистентность `id`** между запусками приложения (восстановление
  `next_id` при загрузке сохранённых данных — см. примечание к
  `GenerateNextId`).
